# 상세페이지(detail) 출력 정책 — 등급별 차등

작성일: 2026-08-26 · 상태: 제안(개발자 확인 대기)

## 배경
- 상세페이지 **장문 생성은 GPT API 토큰 비용이 큼** (현재 비용은 운영자 자비 충전).
- 따라서 **유저 등급별로 detail 출력을 차등**해 비용을 방어한다.
- 본 문서는 기능명세서 **§2의 "detail 글자수 제한 없음"을 아래 등급별 규칙으로 대체**한다.
- **SNS·광고 채널은 무관** — 전 등급 동일(짧게). 이 정책은 **detail 채널에만** 적용.

## 정책

| 등급 | detail 채널 | 출력 | 목적 |
|------|------------|------|------|
| **익명(비로그인)** | **차단** | detail 선택·생성 불가 | 비용 방어(남용 차단) |
| **무료 플랜** | 허용 | **현행 유지** — 짧은 인트로(~90–100자) | 저비용 유지 |
| **유료 플랜(Pro)** | 허용 | **섹션형 장문 · 최대 1,000자** | 유료 가치 |

- A/B 2안: 유료 detail은 **A·B 모두 장문**(≤1,000자), 소구 전략만 다르게.

## 적용 지점

### 프론트(FE) — 안내·차단 UX
- **채널 선택**의 `상세페이지` 칩:
  - **익명** → 비활성 + 자물쇠/“로그인 필요” 툴팁. 클릭 시 가입 소프트월 유도.
  - **무료·유료** → 활성.
- **결과 화면 detail 카드**: 등급에 따라 *짧은 인트로 / 섹션형 장문* 렌더 + 글자수 표시.

### 백엔드(BE) — 실제 강제 (비용 직결 → 필수)
- `POST /generate`에서 **서버가 등급을 검증해 강제**(FE 신뢰 금지):
  - **익명 + detail 요청** → 거부 또는 detail만 제외하고 나머지 채널 생성 + 사유 반환.
  - **무료** → detail 프롬프트 = 현행(짧게).
  - **유료** → detail 프롬프트 = 섹션형 + “1,000자 이내” 지침.
- **길이 상한**: LLM은 글자수를 엄격히 못 지킴 → **프롬프트 지침 + 후처리 상한**(1,000자 초과 시 문장 경계에서 컷) 권장.

## 엣지 케이스
- 익명이 **detail만** 선택 → 칩이 비활성이라 애초에 선택 불가(다른 채널 유도).
- **유료 → 무료 강등**: 이후 생성 detail은 짧게. **기존 히스토리 장문은 그대로 유지**.
- detail 미포함 생성엔 영향 없음.

## ⚠️ 확인 필요(결정 대기)
1. **익명 detail 처리**: 요청 시 에러 반환 vs 조용히 detail만 빼고 생성. → 권장: **FE에서 못 고르게 + BE 방어적 거부**.
2. **크레딧**: 유료 장문이 토큰을 더 써도 **생성 1회 = 2크레딧 유지**? vs detail 장문 가산. → 권장: **유지**(Pro 요금제로 흡수).
3. **무료 detail 상한값**: “현행”의 실제 상한(예: ~120자)을 프롬프트/후처리로 고정할지.
4. **1,000자 초과 컷 방식**: 문장 경계 컷 + “…” vs 재생성.
